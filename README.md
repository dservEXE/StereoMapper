# Стереокамера: расстояние и карта

## Установка для Windows 10/11 x64

Скачайте **StereoMapper-Setup.exe** из [последнего выпуска GitHub Releases](https://github.com/dservEXE/StereoMapper/releases/latest) и запустите его. Это полный установщик: Python, OpenCV и остальные компоненты уже входят в комплект. Системный Python и Git устанавливать не нужно. Установка выполняется для текущего пользователя, создаёт ярлык и сохраняет исследования при обновлении.

Если скачали **Code → Download ZIP**, распакуйте архив полностью и запустите корневой **Install.cmd**. Он загрузит полный установщик с GitHub, проверит размер и SHA-256, затем откроет окно установки. Интернет нужен для загрузки установщика. **StereoMapper-Update.exe** — только маленькое обновление уже установленной программы; для первой установки он не подходит.

**Начиная с 0.13.0**, приложение само проверяет новые стабильные выпуски в фоне. При наличии обновления появляется предложение **«Обновить»**; можно выбрать **«Позже»** или отключить автопроверку. Кнопка **«Проверить обновления»** доступна вручную. Загрузка и замена кода происходят после нажатия, с проверкой SHA-256; карты, калибровки и настройки сохраняются. При отсутствии интернета текущая версия продолжает работать.

`ModuleNotFoundError: No module named 'cv2'` при запуске `main.py` означает запуск исходников через Python без OpenCV. Для обычного использования выбирайте установщик. Для разработки используйте **start.cmd**: он проверяет компоненты `.venv` и восстанавливает неполную установку перед запуском.

**0.12.0 — новый интерфейс.** Четыре понятных экрана: «Камеры», «Калибровка», «Сканирование», «Дополнительно». Главные действия закреплены и доступны в небольшом окне. Пустые изображения объясняют, что сделать; состояние подключения и калибровки видно сверху. Измерение листа перенесено в дополнительные инструменты. В списке сохранённых сеансов карту можно сразу открыть в 3D. Подсказки `?` сохранены; F1 открывает краткий маршрут. [Как пользоваться новым интерфейсом](INTERFACE_GUIDE.md).

**0.10.2:** кисть сразу подсвечивает точки при нажатии и движении ЛКМ. Кружки и мазки накапливаются; Ctrl или режим «Вычесть» убирает точки локально. Сброс — «Снять выделение» или Esc. Круг кисти виден до нажатия.

**0.10.1:** исправлено распознавание Alt в редакторе 3D на Windows: включённый Num Lock больше не переключает прямоугольник, лассо и кисть во вращение. Смена инструмента также завершает выбор меток сшивки. После обновления нужно перезапустить приложение, включая ранее открытые тестовые окна.

Версия **0.10** добавляет общий [редактор 3D-карт](3D_EDITOR_GUIDE.md): свободное вращение мышью, прямоугольник/лассо/кисть, сквозное выделение и видимую поверхность, слой глубины и объём XYZ, удаление/обрезку с отменой, полный экспорт и проекты `.cloudproj`. Можно добавить несколько снимков, совместить их по трём парам общих точек и уточнить положение ICP. Редактирование использует все точки, а не только выборку показа. Исходные PLY и SQLite не перезаписываются.

Приложение на Python + OpenCV для USB-стереопары **HBVCAM-F20271HD-2 V22**, которая определяется в Windows как **DAR_left** и **DAR_right**. Работа с изображениями реализована через стандартный интерфейс USB-камер; специальный протокол этой платы не использован.

Версия **0.9**: исправлена чрезмерная отбраковка обычных поверхностей строгим CUDA-фильтром. В сохранённых сценах число принятых пикселей глубины выросло примерно вдвое при сохранении защиты от повторяющихся ложных совпадений. Добавлены предварительная проверка разнообразия наклонов доски, счётчик ракурсов, иллюстрированная инструкция в приложении и постоянный журнал ошибок. Объёмный снимок позволяет выбрать обычную/строгую защиту, сохраняя три подтверждения поверхности. Сохранение полных моделей, удаление исследований и свободный просмотр 3D сохранены.

**Калибровку начните с [пошаговой памятки и схемы ракурсов](CALIBRATION_GUIDE.md).** В приложении есть кнопка «Как правильно снять калибровку…». Минимум 15 пар и 5 заметно наклонных ракурсов — предварительное условие, а не подтверждение миллиметровой точности.

22.10.2026: подготовлен [обзор 17 научных работ, формул и направлений улучшения](../research/stereo_2026-10-22/stereo_camera_research.md). Исправлено смещение выбранной точки измерения у краёв и пропусков: медианная глубина теперь остаётся на луче выбранного пикселя, а соседи учитываются только при принятой маске `valid`. Добавлены четыре проверки; полный набор из 73 тестов проходит. Физическая точность камеры этим не подтверждается.

**Для клавиатуры с пустотами и «висящими» клавишами:** откройте «Объёмный точный снимок…», задайте область предмета двумя щелчками и начните накопление. Оставьте хорошее освещение и медленно меняйте ракурс. По умолчанию сбор длится до 60 секунд; кнопка «Продолжать до моей остановки» снимает автоматическое ограничение. В [инструкции](SCANNING_GUIDE.md) описаны условия завершения и ограничения. Неподвижный снимок для измерения листа остаётся отдельной функцией.

**Начните с [инструкции по сканированию](SCANNING_GUIDE.md)**: параметры, маршрут для участка 1 × 1 м, точность, ограничения и USB. Для исходников дополнительные зависимости NVIDIA устанавливаются через `setup_gpu.ps1`; в полном установщике компоненты уже включены, нужен совместимый драйвер NVIDIA. Без подходящей NVIDIA доступна обработка на CPU.

## Запуск исходников для разработки

Дважды щёлкните **start.cmd**. Он использует только окружение `.venv` этой папки, проверяет реальные импорты OpenCV-contrib, NumPy, Pillow и tkinter и при необходимости запускает `setup.ps1`. Само наличие `.venv\Scripts\python.exe` больше не считается успешной установкой. Камеры включаются только после нажатия **«Подключить»**.

Для этого способа нужен Python **3.12–3.14 x64 с tkinter**; установщик готовой программы его не требует. При первом запуске исходников нужен интернет. При неудачной установке следующий запуск повторит восстановление. Перенесённое или сломанное окружение сохраняется в `.venv-backup-*`, после чего создаётся новое. Папку `.venv` между компьютерами не переносите.

Для режима одного фото в исходниках дополнительно запустите `setup_photo.ps1`: устанавливаются PyTorch для CPU и Transformers. При первом расчёте исходников загружается модель размером около 100 МБ. В полном установщике модель уже включена. Изображения обрабатываются локально.

## Камера глубины MaixSense A075V

Подключите камеру по USB и проверьте, что её страница открывается в браузере по адресу 192.168.233.1. В приложении выберите режим **MaixSense A075V (ToF)** и нажмите «Подключить камеры». Калибровка и доска не нужны: глубина считается сразу, заводские параметры объектива читаются из камеры. Закройте страницу камеры в браузере перед подключением: она настраивает камеру и мешает приложению.

Карта, объёмный снимок, измерения, 3D-просмотр и экспорт работают как со стереокамерой. Отличия: дальность примерно до 1,5 м и разрешение глубины 320 × 240, поэтому камера подходит для стола, предмета и небольшой комнаты. Частота зависит от порта USB: приложение берёт все кадры, которые отдаёт камера (при проверке было 7–12 в секунду). Двигайте камеру медленно. Слева показывается инфракрасное изображение, справа цветное.

Предметы дальше предела камера показывает ложно близкими. Переключатель **«MaixSense: отсекать ложную глубину»** убирает такие точки и включён по умолчанию; выключите его, если пропадают очень тёмные близкие предметы.

## Взвешивание людей

Экспериментальная оценка на вкладке **«4 Взвешивание»**. При первом открытии программа предложит скачать три модели, 252 МБ; они работают на этом компьютере, кадры никуда не передаются. Камера находит людей, даёт каждому номер на время сеанса, измеряет рост и ширину частей тела и по объёму оценивает массу. Лица не распознаются, а результат сохраняется только числами.

Встаньте целиком в кадр в 2–3 м от камеры и в метре от стены, разведите руки и медленно повернитесь на месте. Нужна облегающая одежда: свободная сильно завышает вес. Оценка не проверена на весах и показывает диапазон; при проверке на одном человеке рост расходился на 11 см между запусками. Со стереокамерой проверена, с MaixSense пока нет: на расстоянии 1,5 м человек не помещается в кадр. Сохранённые эксперименты открываются там же.

**Ускорение.** Программа сама определяет видеокарты компьютера и рекомендует подходящий комплект: кнопка появится на этой вкладке, а все варианты есть на вкладке «Дополнительно». NVIDIA: 2,6 ГБ, самое быстрое. AMD, Intel и другие карты с DirectX 12: 0,2 ГБ. Для встроенной графики комплект обычно не нужен. После скачивания перезапустите программу: при запуске она замеряет, что быстрее, карта или процессор, и использует быстрое. Поиск людей на AMD и Intel всегда идёт на процессоре, а глубину со стереокамеры на видеокарте считает только NVIDIA.

**База людей.** После замера откройте вкладку «База людей», введите в форме справа настоящие рост и вес человека и нажмите «Добавить в базу». Там же видны записи и средняя ошибка, и там же их можно сохранить в CSV для анализа и обучения расчёта. База хранится только на этом компьютере в `data/people`, без снимков, и сохраняется при обновлениях. Записывайте человека только с его согласия; вместо имени подойдёт код. Введённые данные, ошибка замера и качество калибровки записываются и в `result.json` папки замера `output/weighing_<дата>`, так что по одной папке видна погрешность. Для замера «Сейчас» эта папка создаётся сама.

**Оформление.** На вкладке «Дополнительно» можно выбрать тёмную или светлую тему и выключить анимации интерфейса. Тема применится при следующем запуске, анимации переключаются сразу. На расчёты эти настройки не влияют. Окна выбора файла и системные сообщения выглядят так, как задано в Windows.

## 1. Проверка подключения

1. Закройте другие программы, использующие камеры.
2. Начните с индексов **0 и 1**, **640 × 480**, **15 кадров/с**, подключения **AUTO**, режима **«Две камеры»**. Для проверки обрывов подключите камеру непосредственно к USB компьютера, без удлинителя.
3. Нажмите «Подключить». Приложение проверяет шесть последовательных кадров и при необходимости пробует другой формат, меньшую частоту и другой способ подключения. Каждый режим проверяется по фактическому размеру изображения. При повторных обрывах высокого разрешения программа явно переходит на 640 × 480 и отключает несовместимую калибровку. Подбор может занять несколько десятков секунд.
4. Поочерёдно прикройте объективы и убедитесь, что левое изображение соответствует физически левой камере. Если перепутаны — отключитесь, включите «Поменять левую и правую» и подключитесь снова.
5. Если нет изображения, попробуйте другие индексы или подключение MSMF. Индексы могут меняться после переподключения USB; названия DAR_left / DAR_right сами по себе не гарантируют порядок OpenCV.

Начальная проверка **1920 × 1080 / 15 кадров/с через MSMF** давала кадры, но она не доказывает длительную стабильность. Позже при проверке 1280 × 720 обнаружились зависания даже без расчёта глубины. В версии 0.3 отключена дополнительная обработка MSMF при инициализации. После этого **640 × 480 / 15 через MSMF прошёл минутную проверку без обрывов**, с фактической частотой около 8–15 стереопар/с и максимальным промежутком между кадрами 0,162 с. Фактический способ и размер видны внизу; начальные параметры сохраняются в `data/logs/capture_*.json`.

Захват выполняется в отдельном процессе. При отсутствии кадров больше трёх секунд приложение останавливает зависший захват и пробует подключиться заново, сохраняя работоспособность окна. После восстановления накопление карты приостанавливается, поскольку положение камеры могло измениться. Повторные сбои заканчиваются сообщением с причиной. Это помогает при зависаниях драйвера, но не устраняет плохой контакт или недостаточное питание USB.

При подключении расчёт глубины **выключен**, даже если сохранённая калибровка загрузилась. Сначала проверьте живое видео, затем включите **«Рассчитывать глубину»**. Включение накопления карты автоматически включает глубину. Два верхних изображения обновляются независимо от тяжёлого расчёта, без очереди старых кадров. Старые настройки версии 0.2 один раз заменяются на 640 × 480 / 15 / AUTO и сбалансированную обработку шириной 640; копия прежних настроек сохраняется в `settings_before_v03.json`.

Настройки разрешения, порядка камер и параметров расчёта применяются при подключении. Не меняйте фокус, зум и положение объективов после калибровки.

## 2. Калибровка — обязательно для метров

По умолчанию доска имеет **9 × 6 внутренних углов**, то есть **10 × 7 клеток**. Кнопка **«Экранная доска / PNG для печати»** открывает рисунок внутри приложения; отдельная программа для PDF не нужна. Можно менять сетку, сторону клетки в миллиметрах, разворачивать доску по **F11** и снимать пары **пробелом**. **Esc** выходит из полного экрана.

1. В окне доски измерьте линейкой контрольную линию, показанную снизу. Введите измеренную длину и нажмите **«Уточнить масштаб по линейке»**. Начальная оценка Windows может быть неточной. Масштаб сохраняется в `screen_board.json`; при смене монитора или его масштаба настройте его заново.
2. Введите желаемый размер клетки и нажмите **«Построить»**. Если рисунок обрезается, включите полный экран либо нажмите **«Вписать в экран»**. Вписывание меняет физический размер клетки — новый размер показан в окне.
3. Нажмите **«Применить для калибровки»**. Размер передаётся в основное приложение с учётом округления клетки до целого числа пикселей. При изменении сетки или размера начинается новая серия; прежние снимки сохраняются.
4. Подключите камеры в основном окне, вернитесь к доске и снимайте пары пробелом. Окно с предпросмотром скрывается на время снимка, а доска остаётся видимой: повторяющийся рисунок в предпросмотре не мешает поиску углов.

Кнопка **«Сохранить PNG для печати»** сохраняет рисунок и описание размера в `output/boards`. Печатайте в масштабе **100%, без подгонки**, затем наклейте лист на плоскую жёсткую основу. Ранее созданный PDF A4 с клеткой 25 мм также остаётся в `output/pdf/calibration_board_A4_25mm.pdf`.

**Измерьте настоящую сторону напечатанной клетки линейкой** и введите её в миллиметрах. В PDF клетка задана как 25 мм, но настройки принтера могут изменить размер. Ошибка этого размера переносится прямо в масштаб глубины и карты.

Если доска показана на мониторе, измерьте клетку **на самом экране**. Масштаб просмотра PDF или Word меняет её физический размер. В кадре должна быть одна доска: повторный рисунок в окне предпросмотра камеры может мешать поиску. По умолчанию приложение на время съёмки скрывает своё окно и делает снимок через секунду, затем возвращает окно. Для бумажной доски скрытие можно отключить.

1. Введите числа внутренних углов и размер клетки до подключения.
2. Доска должна быть целиком видна в обеих камерах. Перед нажатием остановите **и камеру, и доску**, удерживайте их неподвижно до окончания снимка. Между снимками меняйте ракурс.
3. Снимите **20–30 разных ракурсов**: ближе и дальше, у краёв и в центре, с наклонами вокруг разных осей. Требуется минимум 15; одинаковые ракурсы отклоняются.
4. Нажмите «Рассчитать калибровку». Кнопка показывает, что расчёт идёт; этапы видны в строке состояния. Расчёт выполняется в фоне, живой предпросмотр работает независимо от него.
5. Программа оценит геометрию, базу между камерами и ошибки. Плохая калибровка отклоняется: RMS > 2 px или медианная вертикальная ошибка > 1 px.
6. Проверьте глубину Z по нескольким неподвижным предметам на известных расстояниях, например 0,5, 1 и 2 м, измеренным от камеры примерно вдоль её оптической оси. Низкая ошибка калибровки сама по себе не доказывает точность расстояния.

RMS — ошибка согласования найденных углов с моделью стереокамеры. «Ошибка по строкам» — медианное вертикальное расхождение одинаковых углов после выравнивания. Значения 3,03 и 2,39 px на исходном скриншоте превышают пороги приложения. Это отказ применить неточную калибровку, а не ошибка самого подключения MSMF.

Новая версия сохраняет `quality_report.json` с ошибками отдельных пар. При явно выделяющихся ошибочных снимках допускается исключить до 25% серии, сохраняя минимум 15 пар; исходные фото не удаляются и пороги качества не ослабляются. Пересчёт сохранённой серии 1920 × 1080 улучшил результат до RMS 2,11 px и вертикальной ошибки 2,05 px на 35 из 42 пар, но серия всё ещё отклонена. Для неё нужны более качественные неподвижные снимки.

Калибровка сохраняется в `data/calibration.npz`, копия и исходные пары — в папке серии `data/calibration_...`. При следующем подключении последняя калибровка загружается автоматически, если совпадают индексы, порядок и фактическое разрешение. Если устройства поменялись местами, одинаковые индексы этого не обнаружат: проверяйте объективы вручную.

Сырые пары сохраняются на диск по мере съёмки. Кнопка **«Открыть сохранённую серию…»** позволяет восстановить серию и повторить расчёт при том же порядке камер и разрешении. Найденные углы кэшируются в `detections.npz`.

## 3. Расстояние и текущая карта

После расчёта или ручной загрузки калибровки включается глубина. При автоматической загрузке во время подключения включите её переключателем. Одинаковые точки на выровненных изображениях должны лежать на одних горизонтальных линиях. Щёлкните по объекту на левом изображении или карте глубины:

- **Глубина Z** — расстояние вдоль оптической оси выровненной левой камеры.
- **Расстояние от левой камеры** — длина трёхмерного вектора до выбранной поверхности.

Используется медиана небольшой окрестности щелчка на близкой по глубине поверхности. Щелчок по живому видео запускает измерение **на той паре кадров, которую вы видели при щелчке**; результат подписан «На выбранном кадре» и остаётся фиксированным. Щелчок по карте глубины закрепляет координату пикселя, которая измеряется при обновлениях карты. Распознавания классов объектов и их отслеживания в этой версии нет.

Цвет глубины: синий ближе, красный дальше. Диапазон цветов автоматически подстраивается под сцену и плавно меняется между кадрами; его границы в метрах показаны под картой. Небольшие колебания почти плоской поверхности не растягиваются на всю палитру. Одинаковый цвет на разных сценах может означать разную глубину — смотрите числовую шкалу.

Тёмные области означают **«неизвестно»**, а не пустоту и не свободное пространство. Переключатель **«Оценивать гладкие поверхности для просмотра»** заполняет маленькие окружённые дырки и некоторые однотонные плоские области. Для большой области нужны десятки принятых точек, распределённых по обеим координатам, согласованная плоскость и границы цветовой области. Оценка ограничена оболочкой опорных точек и общей видимостью камер. Если опоры только с одной стороны, поверхность изогнута или глубины противоречат друг другу, область остаётся неизвестной.

Это **отдельный слой предположений**. В цветном виде он показан приглушёнными цветами, на карте — серыми точками; под изображением отдельно указаны доли «измерено» и «оценено». Такие точки не используются для измерения листьев, основного массива глубины и измеренной 3D-модели. Их можно просмотреть кнопкой **«3D с оценкой гладких поверхностей»** и сохранить отдельными файлами. Обычный 3D-просмотр показывает измеренные точки. Оценённая плоскость может ошибаться: совпадение с окружающими опорами не доказывает форму невидимой середины предмета.

Соответствия проверяются в обе стороны. При наличии достаточно распределённых совпадений программа также оценивает их вертикальное расхождение. Если медиана превышает примерно 1,2 пикселя при ширине расчёта 640, пара отклоняется для глубины и не пополняет 3D-карту; предупреждение появляется под картой. При слишком малом числе признаков эта проверка не даёт оценки и не подтверждает хорошее выравнивание. Стекло, блики, однотонные поверхности и закрытые участки часто не дают надёжной глубины.

Если предупреждение исчезает при остановке камеры, вероятно, два USB-потока снимают в разные моменты. Захват обоих кадров до декодирования не обеспечивает аппаратную синхронизацию экспозиции. Двигайтесь медленнее, обеспечьте хорошее освещение. Если расхождение остаётся на неподвижной камере и сцене, проверьте крепление и заново снимите качественную калибровку в том же разрешении.

Вид сверху — проекция восстановленных поверхностей на плоскость **XZ**. В него попадают пол, стены, потолок и предметы на разных высотах. Это не готовая навигационная сетка препятствий: отсутствие точки означает «неизвестно», а не «свободно». Для отделения пола и препятствий нужен следующий этап с оценкой положения камеры относительно земли.

Поле «Предел глубины» отсекает более дальние точки, но не задаёт гарантированную дальность камеры. «Основной поиск» задаёт базовый диапазон StereoSGBM. «Приоритет близких предметов» добавляет поиск больших сдвигов в нескольких перекрывающихся диапазонах, сохраняя обычный диапазон для остальной сцены. Цена — дополнительное время расчёта. Рабочую дальность и погрешность определяют калибровка, база, оптика, разрешение и сцена.

### Близкие объекты: ориентир 10–15 см

Нижняя граница фильтра — **0,05 м**, но это не обещание измерения на 5 см. Для стереозрения одна поверхность должна быть видна обоим объективам. Теперь дополнительные диапазоны поиска строятся с ориентиром на **10 см** и в сбалансированном режиме. Прежний режим ограничивался одним дополнительным диапазоном и на последней калибровке начинал поиск примерно с 14 см.

По умолчанию включено **«Широкое поле зрения»**. Прежнее выравнивание с `alpha=0` сильно увеличивало и обрезало изображение. Новый режим `alpha=1` сохраняет больше исходного поля, пересчитывая проекции и глубину; по краям появляются чёрные области без исходных пикселей. Маски проверяются по настоящим координатам отображения и по найденному соответствию, а не только по вписанным прямоугольникам. Полный размер листа всё равно должен попадать в оба вида.

Для последней калибровки 1280 × 720, база около 59,5 мм, широкий живой расчёт 640 даёт приблизительно **40% общей области на 10 см** и **53% на 15 см**. Это геометрическая доступность, а не доказательство резкости или точности на этих расстояниях. **«Проверить дистанцию 10–15 см»** показывает текущие оценки и масштаб миллиметров на пиксель. Для мелких деталей используйте отдельный полный снимок.

Под показателями калибровки отображаются приблизительные нижние пределы текущего поиска и геометрического перекрытия. Это лучшие теоретические границы; резкость, текстура и доступная область кадра могут увеличить рабочий минимум. Значение «ближняя глубина» внизу — низкий процентиль достоверных измерений, а не минимум одного шумного пикселя.

### Фильтрация шумов и движение

- Проверка соответствий в обе стороны и оценка достоверности WLS.
- Сглаживание с сохранением границ, медианный фильтр и удаление мелких островков по самой глубине, даже если они соприкасаются с большой поверхностью.
- Текстура проверяется в небольшом и более широком окне: мягкие детали кожи и ткани сохраняются лучше, а слабый шум матрицы на однотонной стене не считается деталями сцены. Уменьшена область, которую WLS отбрасывает возле границ; проверки соответствий сохранены.
- Стабилизация между кадрами применяется при достаточно неподвижном изображении и согласованной глубине; при обнаруженном движении отключается. Недостоверные отверстия не заполняются.
- Захват работает отдельно от тяжёлого расчёта; очередь хранит только последнюю стереопару, чтобы старые кадры не накапливались.

По умолчанию выбран сбалансированный режим с приоритетом близких предметов и шириной расчёта 640 пикселей. Если высокое разрешение камеры работает стабильно, его можно оставить на входе: изображения выравниваются и уменьшаются вместе с параметрами проекции, метрический масштаб сохраняется. Для большей детализации выберите подробный режим и ширину 960, 1280 или оригинал; скорость глубины снизится. При выключенном расчёте последняя карта остаётся на экране, живое видео продолжает обновляться.

Фильтрация уменьшает шум, но не исправляет неверную калибровку, расфокусировку и несинхронную экспозицию. Тёмный участок означает отсутствие достоверной глубины.

Сравнение на двух сохранённых стереопарах этой камеры при одинаковых параметрах: доля принятых измерений выросла с **34,1% до 42,4%** и с **29,3% до 37,3%**. Это увеличение покрытия, а не доказательство большей метрической точности. Третья пара со столом имеет медианное вертикальное расхождение около **3 пикселей при ширине 640**, поэтому теперь отклоняется: сглаживание такой пары скрыло бы проблему геометрии. На этих изображениях расчёт исправных пар занимал около 130 мс; реальная скорость зависит от сцены и построения карты.

Дополнительная живая проверка версии 0.4 снова встретила обрывы USB, включая проверку с прежним порядком захвата. Улучшение качества подтверждено на сохранённых изображениях; устойчивость текущего физического подключения не подтверждена. Повторите проверку напрямую без удлинителя. Предыдущий успешный минутный запуск версии 0.3 не гарантирует стабильность следующих запусков.

В версии 0.5 при новой 30-секундной проверке **1280 × 720 / 30 через MSMF** поток передавал около 30 пар/с, окно показывало около 19 обновлений/с, а широкий расчёт 640 с оценкой поверхностей — около 4,8 кадров/с. Обрывов в этой проверке не было, максимальная пауза предпросмотра — 0,108 с. Это проверка текущего запуска, а не подтверждение длительной стабильности или точности на растениях. Сравнение сохранённой комнаты: 26,3% принятых точек в старом обрезанном виде; 37,7% измеренных и 11,7% оценённых в широком виде. Рисунок и отчёт находятся в `output/quality_v05`.

## 4. Накопленная карта при движении

Включите **«Строить карту при движении»**. Выключение приостанавливает накопление, повторное включение продолжает ту же карту, если слежение удалось восстановить. Новую карту начинает кнопка **«Начать карту заново»**. Начало координат — положение выровненной левой камеры в первый успешно отслеженный момент. Двигайтесь медленно, направляйте камеру на резкие неподвижные детали и сохраняйте перекрытие соседних кадров.

Приложение сопоставляет признаки ORB, оценивает движение через PnP/RANSAC по трёхмерным точкам предыдущего опорного кадра и добавляет облако в общую систему координат. Повторные наблюдения внутри ячейки усредняются. **Предела 400 000 ячеек больше нет:** все принятые измеренные ячейки записываются в `data/maps/<сеанс>/measured.sqlite`. Шаг можно уменьшить до 0,5–1 мм для близких предметов; профили комнаты используют 5–10 мм. Шаг карты не является гарантией метрической точности. Оранжевая линия показывает траекторию. Вид сверху охватывает область вокруг исходной камеры и использует ограниченную выборку для быстрого показа. Вращаемый просмотр отдельно ограничивает отрисовку, а экспорт PLY содержит **весь** измеренный архив. После нового сеанса прежний архив остаётся доступен через «Открыть архив всей карты…».

### Счётчики в реальном времени

- **Захват, пар/с** — скорость получения стереопар от камер.
- **Глубина, кадров/с** — фактическая скорость обработки и обновления, с учётом текущей нагрузки.
- **Получено пар / кадров глубины** — сколько пар захвачено и сколько обработано. Они могут различаться: старые пары пропускаются ради меньшей задержки.
- **В карту / пропущено при слежении** — число успешно добавленных кадров и число неудачных попыток после последнего сброса карты.
- **Добавление, кадров/с** — текущая скорость пополнения карты.
- **Задержка, мс** — время от получения пары приложением до завершения её обработки. Задержку внутри USB-драйвера эта оценка не измеряет.

Частота, выбранная в настройках камеры, — запрос драйверу; фактическая скорость отображается отдельно.

При потере слежения новые точки не добавляются. Попробуйте вернуться к последнему успешному ракурсу. Если восстановить слежение не получается, сохраните карту и начните новую. Кнопка «Начать карту заново» сбрасывает накопленные точки и опорный кадр.

В накопленном виде карта показывает **все стороны от начала координат**, включая точки позади камеры; размер обзора увеличивается при выходе маршрута за начальный диапазон. Стрелка показывает оценённое положение и направление камеры. Смещение и поворот выводятся в строке слежения. Само облако сохраняет трёхмерные координаты всех направлений; карта сверху является лишь проекцией XZ.

Хранятся до 40 опорных видов. При потере текущего слежения программа пробует восстановиться по недавно сохранённым видам и первому виду; это помогает при возвращении к знакомому ракурсу после оборота. Координаты признаков учитываются с субпиксельной точностью, чтобы уменьшить округление положения.

**Это экспериментальная визуальная одометрия, а не законченная SLAM-система.** Восстановление по опорному виду не пересобирает уже накопленную карту и не исправляет весь дрейф. Здесь нет глобальной оптимизации петель и удаления движущихся объектов. Непрерывная точная сшивка полного оборота на реальной сцене ещё не подтверждена. Карта обзора не считается источником точных размеров листьев; для больших маршрутов потребуется полноценный stereo SLAM и проверка синхронизации этой платы.

## Листья: измерение и история роста

Цель проекта — различать изменение порядка **1 мм**. Реальная точность этой камеры пока не подтверждена эталонными измерениями.

1. Остановите камеру и растение, обеспечьте резкость и равномерный свет. Нажмите **«Точный снимок · измерить лист»**. Накопление карты приостановится.
2. Приложение получает пять отдельных стереопар, проверяет неподвижность в обоих видах и рассчитывает глубину в **полном исходном разрешении** с меньшим окном сопоставления. Остаются точки, принятые минимум в четырёх кадрах и согласованные по смещению. Дорисованные поверхности исключены.
3. В отдельном окне увеличьте нужный участок колесом и выберите две точки. Вычисляется прямое расстояние между ними в 3D; для изогнутого листа оно не равно длине вдоль поверхности. Повторяемость пяти кадров отражает разброс, а не абсолютную точность.
4. Введите постоянные обозначения растения и листа, выберите «Длина» или «Ширина» и сохраните. Данные дописываются в **`output/leaf_measurements.csv`**, а снимок, глубина и калибровка — в `output/precision_...`. Для сравнения роста сохраняйте одинаковое определение размера и узнаваемые точки листа.
5. Для проверки выберите **«Эталон»**, укажите настоящий размер известного отрезка в миллиметрах и сохраните. Ошибка записывается в CSV. Проверяйте несколько размеров, дистанций и ракурсов, включая 10 и 15 см; единичный удачный эталон не подтверждает точность всей рабочей области.

Живой обзор 640 и карта с ячейкой 5 мм не предназначены для измерения изменения в 1 мм. Подробный снимок использует исходные пиксели до объединения в ячейки, но качество оптики, калибровки, совпадения экспозиций и выбора точек всё равно ограничивает результат.

## Сохранение

«Сохранить снимок и 3D-карту» создаёт папку в `output`:

- `left.png`, `right.png` — выровненная стереопара;
- `raw_left.png`, `raw_right.png` — исходные кадры;
- `depth_metres.npy` — глубина Z в метрах, недостоверные пиксели содержат NaN;
- `depth_color.png`, `map.png` — изображения для просмотра;
- `depth_preview.png`, `depth_interpolated_mask.png` — просмотр с оценёнными поверхностями и их маска; это предположения, а не дополнительные измерения;
- `estimated_surfaces.ply`, `accumulated_estimates.ply` — отдельные оценённые поверхности текущего кадра и накопленные оценки, если они есть;
- `visible_cloud.ply` — цветные точки текущего кадра, если есть достоверная глубина;
- `visible_surface.ply` — треугольная поверхность текущего кадра; отверстия и резкие границы глубины не сшиваются;
- `accumulated_cloud.ply`, `trajectory.csv` — накопленная карта и траектория, если есть точки;
- `calibration.npz` — параметры для выровненных кадров разрешения расчёта;
- `raw_calibration.npz` — исходная калибровка для сырых кадров;
- `metadata.json` — параметры, единицы и счётчики для воспроизводимости.

Оси облака: X вправо, Y вниз, Z вперёд; единицы — метры. «Покрутить текущую 3D-карту» открывает встроенный просмотрщик. Левая кнопка — вращение, колесо — масштаб, правая кнопка — перемещение. «Открыть 3D-модель PLY…» загружает сохранённый файл, в том числе после отключения камер.

Накопленная карта сохраняется как цветное облако точек; поверхность с треугольниками строится для текущего кадра. Встроенный просмотрщик показывает вершины обеих моделей. Для просмотра заполненных треугольников PLY можно открыть в CloudCompare или MeshLab. Поддерживается текстовый ASCII PLY, экспортируемый этим приложением.

## 5. Глубина по фотографии

Откройте **«Глубина по фотографии…»**. Подключение камер для этого не требуется.

**Одно обычное фото:** выберите изображение и нажмите «Рассчитать глубину». Используется [Depth Anything V2 Small](https://huggingface.co/depth-anything/Depth-Anything-V2-Small-hf), модель оценки относительной глубины. Большая предсказанная обратная глубина соответствует близкой поверхности. Цветная карта сохраняется вместе с массивом относительной глубины. Расстояния в метрах не определяются. Иллюстративная 3D-поверхность использует условный масштаб и предполагаемую проекцию; её можно вращать, но нельзя считать точной геометрией сцены.

**Левое и правое фото:** выберите пару, снятую этой камерой одновременно, и загрузите её калибровку для того же разрешения. Результат — стереоглубина в метрах. Для исходных снимков `raw_left.png` / `raw_right.png` выбирайте `raw_calibration.npz`. Для уже выровненных `left.png` / `right.png` выбирайте `calibration.npz` и отметьте «Стереофото уже выровнены», чтобы не исправлять искажения второй раз.

«Сохранить глубину и 3D-модель» создаёт папку `output/photo_...` с цветной картой, массивом глубины, `cloud.ply`, `surface.ply` и описанием единиц. Для одного фото массив называется `depth_relative.npy`, а единицы моделей явно записаны как `relative`. Для стереопары — `depth_metres.npy`, единицы `metres`. Кнопка «Покрутить 3D-модель» открывает результат без внешней программы.

## Что ещё надо проверить именно на этой камере

Наличие двух USB-потоков не доказывает аппаратную синхронизацию экспозиции. Программа сначала захватывает оба кадра и затем декодирует, но не синхронизирует сенсоры аппаратно. Для движения это существенно: начните с неподвижной сцены и медленного перемещения. Достоверной документации изготовителя именно для HBVCAM-F20271HD-2 V22 пока нет, характеристики и точность не предполагаются.

135 тестов проверяют метрическую глубину и сохранение широких проекций при уменьшении, дополнительный поиск на 10 см, близкие поверхности до 6 см на искусственных парах, шумы и границы, отделение оценённых плоскостей от измерений, отбрасывание неверных пар, временную стабилизацию, восстановление USB, геометрию доски, восстановление по опорному виду, показ четырёх сторон карты, модели PLY и полный снимок с отрезком 1 мм на искусственной сцене. Дополнительно проверены сохранение/повторное открытие/полный экспорт более 400 000 точек, неблокирующая очередь карты, совпадение параллельного CPU с обычным, метрическая CUDA-глубина и автоматическое восстановление после сбоя GPU. Это не подтверждение достижения 1 мм или 6 см именно реальной камерой. Окна подсказок, профили, просмотр полного архива с ограничением отрисовки, фоновый экспорт, увеличение, измерение и CSV также проверены через интерфейс с временными данными.

## Необязательные обновления через GitHub, версия 0.12.1

Репозиторий и установщики: https://github.com/dservEXE/StereoMap/releases/latest.

Это обновление кода для существующего полного комплекта StereoMapper. Один раз запустите `StereoMap-Setup.exe` и выберите папку, где уже лежат `StereoMapper.exe` и `runtime`. Для чистого компьютера сначала нужен полный комплект или подготовленная среда по инструкции выше: маленький установщик не содержит Python, CUDA и модель.

После этого приложение проверяет релизы раз в 6 часов; есть ручная проверка, отключение автопроверки и «Позже». Яркая кнопка обновления появляется при новой стабильной версии. Загрузка и установка добровольные. Перед установкой остановите камеры и обработку. Проверяются адрес релиза, размер и SHA-256. Заменяется только папка `stereo`; runtime, модели, data, output, настройки и калибровки сохраняются. При ошибке замены восстанавливается предыдущий код.

Для нового релиза измените `stereo/version.py` и отправьте изменения в main. GitHub Actions проверит обновляющий модуль без камер и GPU и опубликует маленький установщик. Снимки, карты, пользовательские настройки, виртуальная среда и веса модели в публичный репозиторий не входят.
